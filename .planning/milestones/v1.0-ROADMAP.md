# Milestone v1.0: MVP

**Status:** SHIPPED 2026-01-29
**Phases:** 1-4
**Total Plans:** 9

## Overview

Build a Windows system tray application that displays Claude.ai usage limits at a glance. The journey starts with establishing the tray shell and Electron foundation, adds browser-based authentication to access usage data, implements data fetching and visual display with color-coded progress bars, and finishes with background polling to keep limits current. Each phase delivers complete, verifiable capabilities building toward a monitoring tool that shows usage status without requiring browser navigation.

## Phases

### Phase 1: Electron Shell + Tray Foundation

**Goal**: Users see a persistent system tray icon with basic interaction
**Depends on**: Nothing (first phase)
**Plans**: 2 plans

Plans:
- [x] 01-01-PLAN.md — Scaffold project with electron-vite, create tray icon assets, implement main process with tray and single instance
- [x] 01-02-PLAN.md — Implement popup window with positioning, toggle, and basic UI shell

**Details:**
- System tray icon appears and persists after Windows Explorer restarts
- Hovering over tray icon shows tooltip with application name
- Right-clicking tray icon displays context menu with Refresh, Settings, Login, and Exit options
- Clicking tray icon opens a popup window positioned near the tray
- App enforces single instance (prevents multiple tray icons if launched twice)

### Phase 2: Browser Authentication

**Goal**: Users can log in via browser and maintain authenticated session
**Depends on**: Phase 1
**Plans**: 2 plans

Plans:
- [x] 02-01-PLAN.md — Create auth module with session management, gray tray icon, and IPC handlers
- [x] 02-02-PLAN.md — Update popup UI for auth state display and verify complete login flow

**Details:**
- User can click Login option and browser window opens to Claude.ai sign-in page
- After user completes login, auth window closes and app shows "Logged in" in popup
- User closes app and relaunches without needing to log in again (session persists)
- When session expires, app detects this and prompts user to re-authenticate from popup

### Phase 3: Data Fetching + Display

**Goal**: Users see their current usage limits with visual indicators
**Depends on**: Phase 2
**Plans**: 3 plans

Plans:
- [x] 03-01-PLAN.md — API module with usage fetching, types, state management, and IPC handlers
- [x] 03-02-PLAN.md — ProgressBar and UsageDisplay UI components with gradient styling
- [x] 03-03-PLAN.md — Integration into App.tsx, tray icon color updates, and human verification

**Details:**
- Clicking tray icon shows popup with three progress bars (session limit, weekly all-models, weekly Sonnet-only)
- Each limit displays current usage percentage, numerical values, and countdown until reset
- Tray icon color reflects most limiting constraint (green < 70%, yellow 70-90%, red >= 90%)
- User can click Refresh in popup or context menu to manually update data
- When network fails, popup shows last-known data with "Last updated X minutes ago" indicator
- The most limiting metric is visually emphasized in popup (highlighted or positioned first)

### Phase 4: Background Polling + Settings

**Goal**: Usage data stays fresh automatically with user control over behavior
**Depends on**: Phase 3
**Plans**: 2 plans

Plans:
- [x] 04-01-PLAN.md — Install dependencies, create settings module with electron-store, polling module with exponential backoff, wire into app lifecycle
- [x] 04-02-PLAN.md — Add settings IPC handlers, Settings UI component with slider and toggle, integrate into popup

**Details:**
- App fetches usage data in background every 5 minutes (default) without user action
- Tray icon color and popup data update automatically when new data arrives
- User can open Settings dialog and change polling interval (1 min to 30 min range)
- User can enable/disable "Start with Windows" from Settings, and app respects this on next boot
- App implements exponential backoff when network errors occur (prevents aggressive retry loops)

## Milestone Summary

**Key Decisions:**
- electron-vite for modern Vite-based build tooling
- BrowserWindow for login instead of shell.openExternal (Electron session isolation)
- Cookie polling with cookies.on('changed') for auth detection
- net.request with useSessionCookies for reliable API cookie handling
- electron-store for settings persistence
- Recursive setTimeout for polling (allows dynamic interval changes)
- Exponential backoff with auth error detection stops retry loops

**Issues Resolved:**
- ImageMagick not available for icon conversion — solved with Node.js binary manipulation
- electron-store ESM/CJS compatibility — solved with require + .default fallback pattern
- System browser cookies separate from Electron — solved with BrowserWindow for login

**Technical Debt Incurred:**
- Orphaned export: closeLoginWindow in browser.ts (unused utility)
- Type duplication across preload and renderer components
- Context menu Settings item logs to console only (accessible via gear icon)
- tray:action IPC channel defined but unused
